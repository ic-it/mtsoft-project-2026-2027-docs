MTSOFT — общий документ Project 1 в Typst
======================================

Сборка из корня этого репозитория:

  mkdir -p build
  typst compile main.typ build/MTSOFT.pdf
  typst watch main.typ build/MTSOFT.pdf

Нужны Typst 0.15.1 и установленный Times New Roman. PDF лежит в build/
и не коммитится. Сборка не использует Python, конвертеры, сетевые пакеты,
Google Docs или DTS. Проверки расчётов выполняются самим Typst.

Git identity для этого клона
---------------------------
В .gitconfig сохранены email ic-it@mail.com и commit.gpgsign=false:
обычные будущие коммиты не используют глобальную GPG/X.509-подпись.
Имя автора не меняется. Это не анонимные коммиты: имя и email остаются
в стандартных полях author/committer.

Git не подключает версионируемый .gitconfig автоматически. В текущем
клоне он подключён через локальный include.path. После нового clone
можно явно включить эти настройки одной командой из корня репозитория:

  git config --local --add include.path ../.gitconfig

Подключать нужно один раз, не перед каждым коммитом. Это настройка
конкретного клона; коллегам не нужно включать её, если они хотят свой
email. Глобальный ~/.gitconfig и другие репозитории не меняются.
Явные git -c, git commit -S и GIT_AUTHOR_EMAIL/GIT_COMMITTER_EMAIL могут
переопределять defaults. Старые коммиты эта настройка не переписывает.

Структура и редактирование
-------------------------
main.typ                    Порядок глав, титульник и оглавление.
template.typ                Общая типографика, таблицы и колонтитулы.
chapters/01-context.typ      Контекст и цели Q1–Q5.
chapters/02-organisation.typ RACI, FTE и коммуникация.
chapters/03-stories.typ      Восемь Stories, AC и условия проверки.
chapters/04-quality.typ      Качество требований и открытые вопросы.
chapters/05-traceability.typ Исходная матрица с объединениями ячеек.
chapters/06-risks.typ         Исходный Risk Register.
chapters/07-approach.typ      §3.6: подход, уровни, типы, риск и приоритет.
chapters/08-sprints.typ       §3.6: три спринта, зависимости и нагрузка.
chapters/09-environments.typ §3.6: среды, платформы и данные.
chapters/10-reporting.typ     §3.6: метрики, отчёты и дефекты.
chapters/11-criteria.typ      §3.6: DoR, entry, DoD и Release 1.
chapters/references.typ      Список источников [01]–[04].
data/capacity.typ            Единый источник чисел бюджета и assert-проверки.
assets/fiit-logo.jpg         Логотип FIIT.
reference/                  Неизменённые исходные материалы.
.github/workflows/release.yml Сборка и Release при каждом push.

Текст написан вручную обычным Typst, без промежуточной модели абзацев
или страниц PDF в качестве фона. AC используют checks(...), таблицы —
report-table(...). В Traceability x/y и rowspan задают реальные связи
объединённых ячеек; их нельзя менять как произвольное оформление.

Для новой главы создайте файл в chapters/ и включите его в main.typ.
Оглавление обновится автоматически. Главы 7–11 могут продолжаться на
одной странице: это устраняет почти пустые страницы между разделами.

Часть 3.6 и границы изменений
----------------------------
Главы 7–11 — новый словацкий план Illia. Это план будущего тестирования,
не отчёт о фактическом исполнении. Конкретные Test Cases для Project 1
не требуются; метрики описывают последующую реализацию плана.

Главы 1–6, исходные AC, Traceability, проценты, ID, приоритеты Stories,
владельцы и оценки рисков при добавлении 3.6 не изменены. Не изменены
также template.typ, прежние источники и workflow. Google Docs и DTS
не редактировались. Коммит, push и публикация агентом не выполнялись.

Приоритет конкретного теста в главе 7 может быть выше приоритета Story
в главе 5: High-риск REQ-227 требует P0-проверки, хотя US08 имеет P2.
Это открытое правило нового плана, не скрытая замена данных матрицы.
Q1 сохраняет 100% выполнение и успех всех запланированных P0/P1.
Q4/Q5 требуют подтверждения PO, как и в исходной главе 1.

В data/capacity.typ числа хранятся в сотых MD, без ошибок float-сумм.
Из них строятся бюджетные таблицы. Компиляция проверяет суммы по ролям,
лимиты спринтов, распределение работы TA, дневной лимит представителя
управляющего и отсутствие формального UAT до D13. 1 MD = 8 часов — наша
плановая конвенция, а не дополнительное требование задания.

Перед сдачей общего документа
----------------------------
1. Командой согласовать новый план: распределение Stories по спринтам,
   правило приоритета тестов, оценки MD, gates и способ измерения Q4/Q5.
   Сейчас это предлагаемый план, а не уже состоявшаяся акцептация PO.
2. Владельцу Traceability сверить реальные DTS-ID и связи: в главе 3
   остаются TC01–TC13, пустые [] и «doplniť ID z DTS», в главе 5 — REQ-357.
   При добавлении 3.6 они не заменялись предположительными ID.
3. Перепроверить знаменатели и непокрытые AC в матрице. Низкие исходные
   проценты сохранены; глава 10 объясняет измерение, но не пересчитывает
   таблицу за её автора и не объявляет частичное покрытие полным.
4. Владельцу Risk Register проверить полноту обязательных полей §3.5:
   в текущем документе показаны оценки и owners, но для каждого риска
   ещё нужны явные причина/событие/последствие, mitigation, trigger и
   влияние на тестовый объём. Новый тестовый подход не заменяет эти поля.
5. Проверить общий объём. В задании рекомендовано 8–12 страниц без
   приложений, это не жёсткий предел. Исходные главы сохранены целиком;
   сокращение или перенос в приложения требует отдельного решения команды.
6. CSV из DTS, презентация и финальный ZIP — отдельные deliverables.
   Добавление 3.6 само по себе не означает готовность всего комплекта.

Источники и проверка
--------------------
reference/MTSOFT-original.pdf — исходник сохранённых глав 1–6 и списка
источников. Страницы оригинала указаны в комментариях этих файлов.
SHA-256: c578af15b8906f68d33d23af699412a472a9c02720f1869fb13ec4b6b3bbfded

reference/Projekt1_zadanie_pre_studentov_v2.1.docx — точная копия задания,
на которое ссылается источник [01]. Главы 7–11 содержат ссылки на разделы
§1.1–1.5, §3.2, §3.4 и §3.6. Номера страниц DOCX не предполагаются:
локатором служит номер раздела. Плановые решения явно отделены от
ограничений задания в тексте и завершающих ссылках глав.

После изменений проверьте PDF целиком: читаемость, продолжение таблиц,
оглавление и переносы. Исходная точность глав 1–6 проверяется отдельно
от содержимого новых глав: сравнивать весь расширенный документ со
старым PDF на полное равенство больше нельзя. Удалённый verify.py
не восстановлен и для сборки не нужен.

Автоматические GitHub Releases
-----------------------------
Workflow находится в .github/workflows/release.yml относительно корня
общего репозитория. Каждый push в любую ветку или тег создаёт отдельный
Release с MTSOFT.pdf; удалённые refs пропускаются. Есть workflow_dispatch.
Тег: build-<run_id>-<attempt>-<short_commit_sha>. Старые релизы не меняются.
Latest обновляет только сборка актуального head основной ветки.

Используется windows-2022, Typst 0.15.1 с проверкой SHA-256 архива и четыре
системных варианта Times New Roman. При ошибке компиляции или отсутствии
шрифта релиз не создаётся. Нужны разрешённые Actions и GITHUB_TOKEN
с contents:write; отдельный PAT не требуется. Workflow не меняет настройки
репозитория. Наличие локального PDF не подтверждает запуск CI.
