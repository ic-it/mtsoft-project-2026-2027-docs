MTSOFT — ручная вёрстка в Typst
==============================

В отдельном общем репозитории, где main.typ лежит в корне:

  typst compile main.typ MTSOFT.pdf
  typst watch main.typ MTSOFT.pdf

В текущем учебном репозитории из его корня:

  typst compile project-1/typst/main.typ project-1/typst/MTSOFT.pdf

Автоматическая пересборка при редактировании в учебном репозитории:

  typst watch project-1/typst/main.typ project-1/typst/MTSOFT.pdf

Нужны Typst 0.15.1 и установленный Times New Roman. Сборка локальная,
без Python, конвертеров, сетевых пакетов и доступа к Google Docs или DTS.

Структура
---------
main.typ                 Порядок глав, титульник и автоматическое оглавление.
template.typ             Общая типографика, таблицы, подписи и колонтитулы.
chapters/01-context.typ   Контекст, stakeholders, цели качества.
chapters/02-organisation.typ  RACI, мощности, коммуникация.
chapters/03-stories.typ   Все восемь Stories, их AC и условия проверки.
chapters/04-quality.typ   Оценка качества, открытые вопросы и предложения.
chapters/05-traceability.typ  Матрица с исходными объединениями ячеек.
chapters/06-risks.typ     Risk Register, продуктовые и проектные риски.
chapters/references.typ   Источники.
assets/fiit-logo.jpg      Исходное изображение логотипа FIIT.
reference/MTSOFT-original.pdf  Неизменённый оригинал пользователя.
verify.py                Только проверка PDF, не импортёр и не конвертер.
.github/workflows/release.yml  Сборка и GitHub Release на каждый push.
.gitignore               Генерируемые файлы, которые не нужно коммитить.

Автоматические GitHub Releases
-----------------------------
Перенесите СОДЕРЖИМОЕ этой папки в корень нового общего репозитория,
включая скрытую папку .github. Итоговый путь workflow в новом репозитории:
  .github/workflows/release.yml
Если оставить его вложенным в project-1/typst/, GitHub его не обнаружит.

На каждый push в любую ветку или тег собирается новый PDF и создаётся
отдельный Release с вложением MTSOFT.pdf. Удаление ветки/тега пропускается.
Доступен также ручной запуск через Actions -> Build and release PDF ->
Run workflow. Для ручного запуска workflow должен быть в основной ветке.
Нет фильтра по файлам и нет отмены предыдущих сборок новым push.

Тег релиза: build-<run_id>-<attempt>-<short_commit_sha>.
Релиз всегда привязан к собранному commit SHA. Повторный запуск получает
новый тег; старые релизы и вложения не перезаписываются и не удаляются.
Latest обновляется только сборкой актуального head основной ветки.
Сборки остальных веток/тегов создают обычные релизы, но не заменяют Latest.
Если сборка не проходит, новый релиз не публикуется.

Сборка идёт на windows-2022. Typst закреплён на версии 0.15.1; SHA-256
официального Windows-архива проверяется перед запуском. Все четыре
варианта Times New Roman должны присутствовать в системных шрифтах.
Если шрифт пропадёт из runner image, workflow завершится явной ошибкой.
Сами файлы Microsoft-шрифтов в репозиторий не копируются.

Отдельный PAT или секрет добавлять не нужно: используется GITHUB_TOKEN
с правом contents:write, заданным в workflow. В репозитории должны быть
разрешены GitHub Actions и запись Releases/tags для этого токена;
правила организации/репозитория могут ограничивать эти разрешения.
Настройки находятся в Settings -> Actions -> General. Workflow сам
не меняет эти настройки и не обходит правила защиты тегов.

В CI не запускается verify.py: это разовая проверка точного переноса
старого оригинала, которая после будущего дополнения текста не подходит
как обязательный тест. CI проверяет успешную компиляцию и наличие PDF.
Собранный PDF лежит в build/ и прикладывается к Release, а не коммитится.

Как редактировать
-----------------
Обычный текст и заголовки написаны обычным Typst. Строка в таблице —
один кортеж из ячеек, а не набор индивидуальных настроек абзаца.
AC заданы через checks([первый критерий], [второй критерий], ...):
нумерация и переносы создаются Typst. Общие настройки — в template.typ.

В Traceability координаты x/y и rowspan нужны для исходных вертикальных
объединений; они сохраняют связи между Story, рисками, TC и покрытием.
Чтобы добавить главу, создайте .typ в chapters/ и включите её в main.typ.
Оглавление обновится само. Страницы PDF не используются как фон.

Что изменено и что не изменено
-----------------------------
Шаблон и все главы написаны вручную. Предыдущие import_docx.py,
content.typ и source-model.json убраны. Нет этапа конвертации или
генерации исходников. Параметры вёрстки не привязаны к координатам
строк оригинального PDF.

Изменены оформление таблиц, межстрочные интервалы, ширины колонок,
разбиение на страницы, колонтитулы и оглавление. Оглавление отражает
фактические главы и страницы, в том числе 5 и 6, отсутствовавшие в
старом оглавлении. Добавлена нумерация страниц. Это не пиксельная копия.

Текст, данные, исходная нумерация разделов, ошибки и незаполненные
пометки сохранены. Например, REQ-357, исходные проценты, TC01–TC13,
«[doplniť ID z DTS]», ссылка на главу 11 и двойная точка в Q4 не исправлены.
Это отдельные вопросы для будущей содержательной работы.

Новая часть пользователя (пункт задания 3.6) не добавлена. Google Docs,
DTS и прежний комплект сдачи не изменены.
